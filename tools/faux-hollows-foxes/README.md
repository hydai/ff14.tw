# 宗長計算機

專為 Final Fantasy XIV 玩家設計的 Faux Hollows Foxes（宗長）活動輔助工具：照你在遊戲裡看到的障礙物與翻開的結果，算出每個還沒翻的格子是劍或寶箱的機率，並框出下一個該翻的格子。

## 功能特色

### 狀態列一步一步帶著做
- 盤面上方的狀態列寫現在要做什麼、還能翻幾次：① 點遊戲裡被擋住的格子（有確定的障礙物之後加「・已知 N／5」）→ ② 找劍 → ③ 找寶箱 → ④ 翻宗長（不一定有）→ 完成
- 一局最多翻 11 格；剩的次數不夠翻完劍或寶箱時，直接跳到下一個目標
- 下一個該翻的格子框綠色，有好幾個一樣好的就全部框起來

### 障礙物自動補上
- 標障礙物時，能標的格子顯示障礙物機率；不可能是障礙物的格子變淡、點不了
- 能確定的障礙物自動補上（斜線加虛線框，和手動標的實心障礙物分得出來），拿掉手動標的，它補上的跟著消失
- 擺法只剩一種就進入翻格，手動標的與自動補上的障礙物都鎖住，要改請按「上一步」

### 格子上的機率與 🦊
- 還沒翻的格子寫劍、寶箱的機率，例如 `⚔️75%`、`📦13%`，0 不寫；只有一個提示的格子，圖示一行、百分比一行
- 劍用藍底、寶箱紅底、宗長黃底；一種候選填滿一格，兩種各半，三種各佔三分之一
- 「隱藏機率／顯示機率」只切換百分比數字，保留兩個階段的候選底色、圖示、已翻開的結果與下一格綠框
- 宗長只放 🦊，意思是「宗長有出現的話，可能在這格」，不寫數字；找到宗長之後，其他格就不再放 🦊
- 格子的名稱（給螢幕閱讀器）也寫出這些提示，例如「第 27 格：劍 75%，寶箱 13%，建議翻這格」

### 格子旁的小選單
- 翻開一格後點它，在格子旁邊選劍、寶箱、宗長或空；上三列開在格子下方，下三列開在上方
- 和其他格對不上的選項是灰的（宗長只有一隻，別格已經是宗長時宗長是灰的）；只剩一種可能時，點一下就標好，不開選單
- 點標好的格子是同一個選單：目前的標成已選，最後多一個「清除」；翻了好幾格之後回頭改早先的一格，機率、🦊、下一格與剩幾次都跟著重算

### 上一步、重做與重置遊戲
- 「上一步」退回最後一個動作，並用 toast 寫出退回了什麼，例如「已退回：第 26 格標成劍」
- 「重做」恢復剛退回的動作；退回後做了新動作，就不能重做舊分支
- 「重置遊戲」另放一整行，清空盤面開始新的一局；按錯了按「上一步」可以救回來，也能重做重置

### 鍵盤與螢幕閱讀器
- 36 個格子都是按鈕，可以用鍵盤操作：Enter 標障礙物或打開小選單，用鍵盤打開時焦點直接在第一個能選的選項，Esc 關掉小選單
- 焦點所在的格子鎖住時（例如標完障礙物進入翻格），焦點自動移到下一格，不會掉到頁面上

## 使用說明

### ① 標障礙物
1. 看遊戲裡被擋住的格子，在這裡點同一格；點已經標的格子可以拿掉
2. 狀態列寫「已知 N／5」；能確定的障礙物會自動補上，不用自己一個一個標
3. 擺法確定後，狀態列變成「② 找劍・剩 11 次」，進入翻格

### ②～④ 翻格
1. 照狀態列的目標，翻綠框的格子（遊戲裡）
2. 回到這裡點同一格，在小選單選翻到的是劍、寶箱、宗長還是空
3. 狀態列依序是「② 找劍」→「③ 找寶箱」→「④ 翻宗長（不一定有）」，剩的次數不夠翻完劍（或寶箱）時直接跳到下一個；劍和寶箱都不用再找（翻完了，或剩的次數來不及翻完），宗長也不用再翻（已經找到，或宗長的位置全部翻開都是空的），就是「完成」；次數用完也是「完成」
4. 標錯了：點那一格改選或清除，或按「上一步」
5. 要玩下一局：按「重置遊戲」

## 技術實作

### 資料與狀態
```javascript
// board-data.js 的 252 種 6×6 盤面（一列一個陣列），hollows-solver.js 的 flatten() 一列接一列轉成長度 36 的陣列
// 格子編號 0–35，第 r 列（0 起）第 c 格是 r × 6 + c；畫面與格子名稱寫「第 p+1 格」
0 = 空
1 = 障礙物
2 = 劍（2×3 或 3×2，6 格）
3 = 寶箱（2×2，4 格）
4 = 宗長或空（宗長 1×1，4 格裡最多出現在其中一格，沒有出現的那些格子就是空；值 4 的格子叫「宗長的位置」）

// script.js 的 state：長度 36，每一格是 null（還沒標）或
'obstacle' | 'sword' | 'chest' | 'fox' | 'empty'   // 自動補上的障礙物不存進 state
```

### FauxHollowsSolver 的規則（`hollows-solver.js`）
`FauxHollowsSolver` 不碰 DOM、不靠 `this`，盤面資料當參數傳進去，所以可以單獨測試。對外有 `flatten()`、`analyze()`、`choices()`、`formatPercent()`。
- **對得上**：每一個有標的格子都相容，沒標的什麼都可以：障礙物對 1、劍對 2、寶箱對 3、宗長對 4、空對 0 或 4
- **障礙物階段**（`analyze()` 的 `phase: 'obstacles'`）：只看手動標的障礙物，數出和它們對得上的盤面，再數每一格在這些盤面裡是障礙物的次數 c。c 等於盤面數的格子是已知的（`known`），其中不是手動標的就是自動補上的（`auto`）；c 介於 0 與盤面數之間的格子還能標（`obstacleCells`），`obstacle` 是每格 c／盤面數的比例；每一格的 c 不是 0 就是盤面數時，擺法確定，進入翻格（`phase: 'reveal'`）
- **翻格階段**：用整份狀態找對得上的盤面（`matches`），每個還沒翻的格子是劍、寶箱的比例 ＝ 對得上的盤面裡這格是劍（寶箱）的種數 ÷ 對得上的種數，每種盤面一樣可能；`left` ＝ 11 − 已翻開的格數
- **目標與下一格**（`goal`、`next`）：照順序判斷，劍還沒翻完而且剩的次數夠翻完 → 劍；否則寶箱還沒翻完而且夠翻完 → 寶箱；否則還有格子放 🦊 → 宗長；都不是就是完成（`goal: null`）。下一格是還沒翻的格子裡目標的種數最大的，同分全部列出；比的是「幾種盤面」這個整數，不除成比例再比
- **宗長不給比例**（`foxCells`）：宗長多常出現沒有公開，算不出實際的機率；而拿盤面的比例當機率會騙人，「假設這局有宗長」的比例每翻開一個空格就往上加（只剩 1 種盤面時 25% → 33% → 50% → 100%），「可能有宗長的盤面占幾成」在劍確定後會讓 4 格同時寫 100%。所以 `analyze()` 只回傳 🦊 放在哪些格子（還沒找到宗長時，是宗長位置的種數大於 0 的格子，找到之後是空的），宗長只在決定「④ 翻宗長」的下一格時用「這格是還沒翻開的宗長位置」的盤面種數排先後
- **`choices(boards, state, position)`**：把這格當成還沒翻開（已經翻開的格子也一樣），看和其他格還對得上的盤面裡這格可能是什麼，照劍、寶箱、宗長、空的順序；別格已經是宗長時不列宗長；手動標的與自動補上的障礙物是 `[]`
- **`formatPercent(fraction)`**：整數百分比，本身就帶「%」；0 不寫，大於 0 但不到 1% 寫「<1%」

### 頁面（`script.js`）
- `FauxHollowsFoxes` 每次 `render()` 都從 36 格的狀態呼叫 `FauxHollowsSolver.analyze()` 重新算（252 種盤面，很快），再把結果畫出來；36 個格子是 `index.html` 裡的按鈕，重畫只改內容與屬性，不重建，焦點才留得在同一個元素上
- 整個盤面只聽一次 `click`（事件委派）；小選單用共用的 `CellPopover`（`assets/js/cell-popover.js`），選項排 2 欄，Esc、點外面、焦點移出由小選單自己關
- `tapCell()`、`choose()` 自己也擋，不靠格子的 `disabled`：不可能的格子與選項、鎖住的障礙物、次數用完時還沒翻的格子，直接呼叫也什麼都不變
- 每個盤面動作之前存一份到 `undoStack`；上一步與重做在 `undoStack`、`redoStack` 之間搬移快照，新動作清除重做分支。切換機率顯示不改歷史；歷史按鈕不能按時用 `aria-disabled`，保留焦點
- 頁面上的文字用 `data-i18n` 與 `FF14Utils.getI18nText()`，繁體中文、English、日本語的翻譯在 `assets/js/i18n/translations/tools/faux-hollows-foxes.js`

## 開發筆記

### 關鍵設計決策
1. **宗長不寫數字**：只放 🦊，原因見上面「宗長不給比例」
2. **每次都重新算**：畫面上的每個字都從 36 格的狀態重新算出來，自動補上的障礙物不存進狀態，所以拿掉手動標的、按「上一步」或回頭改早先的一格，都不會留下過期的結果
3. **不會走到沒有答案**：不可能的格子與選項點不了，選單只列和其他格還對得上的選項，盤面不會變成 0 種
4. **次數不夠就跳到下一個目標**：剩的次數翻不完劍時直接找寶箱，翻不完寶箱時直接翻宗長
5. **小選單而不是對話框**：選項開在格子旁邊，不像對話框蓋住整個盤面；只剩一種可能時連選單都不開

### 效能
- 盤面資料直接放在 `board-data.js`，不用網路請求
- 事件委派處理格子點擊，格子重畫不重建
